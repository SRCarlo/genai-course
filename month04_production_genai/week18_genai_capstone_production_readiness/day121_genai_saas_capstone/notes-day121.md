# Day 121 — GenAI Evaluation & Regression Testing

## Goal
Build a repeatable evaluation workflow for the GenAI SaaS capstone.

## Key concepts
- Unit tests validate individual functions.
- Integration tests validate interactions between components.
- AI evaluation measures relevance, groundedness heuristics, and expected behavior.
- Regression tests detect quality changes after modifications.
- Fixed datasets make evaluation repeatable.
- LLM-as-judge can assist semantic evaluation but needs validation.

## Files
- `evals/datasets/chat-cases.json`
- `evals/evaluator.js`
- `evals/run-evals.js`
- `evals/evaluator.test.js`
- `evals/chat-adapter.js`
- `evals/results/latest.json` (generated by the runner)

## Commands
- `npm run test:eval`
- `npm run eval`
- Optional Groq mode: set `GROQ_API_KEY` and `EVAL_USE_GROQ=true`, then run `npm run eval`.

## Limitations
- Keyword overlap is not a reliable semantic-groundedness metric.
- Deterministic fixtures validate the evaluation framework, not the real LLM.
- Real-model results may vary.
- Tenant isolation and authorization require independent security tests.
- Production evaluation should track quality, latency, cost, citations, and failures.
